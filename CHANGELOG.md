Формат — [Keep a Changelog 1.0.0](https://keepachangelog.com/en/1.0.0/),

## [0.1.14] - 2026-08-22

### Added

- Второй сценарий записи — «сначала услуга»: с плитки «Услуги» (на главной и в
  истории) открывается каталог всех услуг клиники, после выбора услуги
  показываются только филиалы, где её оказывают, дальше — врач и дата/время.
  Если филиал один, он остаётся в списке единственным и подсвечен как выбранный,
  подтверждает выбор всё равно пользователь.
- Кнопка «Повторить» в карточке истории работает: подставляет филиал, услугу и
  врача из прошлой записи (`startRepeat()` в `useBooking`, маппинг —
  `repeatSelection()` в `useAppointments`) и ведёт сразу на выбор даты и времени.
  Дата и время не переносятся — они в прошлом. Если в записи не хватает филиала,
  услуги или врача, пользователь попадает в обычный флоу с уже подставленным
  остальным.
- `startBooking(kind)` в `useBooking`: точки входа задают порядок шагов
  (`branch` — филиал → услуга, `service` — услуга → филиал) и сбрасывают
  выбор от предыдущей записи.
- Отмена записи с главной: кнопка «Отменить запись» под слайдером отменяет ту
  запись, которая сейчас на экране (`cancel()` в `useAppointments`,
  `POST /appointment/cancel`).
- Хелперы в `api/branches`: `getAllServices()`/`loadedAllServices()` (каталог
  услуг из вложенных списков филиалов, без дублей) и
  `getBranchesWithService()`/`loadedBranchesWithService()`.

### Changed

- Сетка времени на экране записи больше не зависит от расписания врача:
  показываем статичные часы рабочего дня клиники (09:00 … 18:00, шаг час),
  записаться можно на любой из них. Ограничение одно — не раньше чем через час
  от текущего времени (в 13:20 ближайший доступный час 15:00, 14:00 уже нет);
  на другие дни доступны все часы. Запрос `coworker/get-schedule` с экрана убран
  вместе с его лоадером и ошибкой загрузки.
- История (`/active`) показывает только завершённые записи — выполненные (`5`)
  и отменённые (`6`). Все остальные статусы (лист ожидания, отправлено в МИС,
  напоминание, подтверждено, а также записи без статуса) идут в слайдер
  актуальных на главной. Деление строго по статусу: `isCurrent()` больше не
  смотрит на дату, поэтому запись, время которой прошло, а бэкенд её ещё не
  закрыл, не пропадает из обоих списков.
- Анимация нажатия стала быстрее на один шаг: блоки выбора, плитки и карточки —
  `duration-100` → `duration-75`, кнопки (`UiBtn`, время, период, «Повторить») —
  `duration-75` → `duration-50`.
- Иконка записи в истории теперь по статусу: `5` (выполнено) — галочка,
  `6` (отменено) — крест, остальные статусы (лист ожидания, отправлено в МИС,
  напоминание, подтверждено) — часы. Вместо булева `canceled` карточка
  принимает `status`, вид считает `statusKind()` в `api/appointments`.
- Врачи и услуги берутся из `/branch/index` — они приходят вложенными в филиал
  (`coworkers[]`, `services[]`), поэтому запрос `/coworker/index` и его кеш
  убраны; в `api/coworkers.js` осталось только расписание. На экране врачей
  показываются только те, кто оказывает выбранную услугу.
- Адрес филиала в списке сокращается до улицы и дома: «город Улан-Удэ, Павлова,
  59А» → «ул. Павлова, 59А».
- Порт dev-сервера зафиксирован (`5174`), чтобы URL туннеля не переезжал.

### Fixed

- Экран филиалов: ранее выбранный филиал больше не остаётся выбранным, если
  выпал из списка после смены услуги — подставляется первый доступный.

## [0.1.13] - 2026-08-20

### Changed

- Сессия клиента живёт только пока открыта страница: токен, `client_id` и
  телефон хранятся в памяти, `localStorage` не используется вовсе. При каждой
  загрузке приложение заново ищет клиента по номеру и получает свежий токен.
- `checkAuth()` всегда берёт номер из `TEST_PHONE`, а не из сохранённого ранее:
  правка константы подхватывается сразу, без чистки хранилища.

### Removed

- Сохранение флагов согласий: они нигде не читались и на бэкенд не уходили.
  Чекбокс рассылки на экране согласий больше не предзаполняется.

## [0.1.10] - 2026-08-19

### Added

- Регистрация клиента, если номера нет в базе: `POST /user/register-telegram?source=max`
  отдаёт клиента с `access_token` без авторизации и без `chat_id`. Вход по
  телефону теперь либо находит клиента, либо создаёт его.
- `src/session.js` — сессия клиента (`token`, `clientId`, `phone`) реактивными
  `ref`, синхронизированными с `localStorage`.
- Выход по `401`: протухший токен чистит сессию и возвращает на экран входа,
  иначе экраны молча упирались в ошибку при каждом запросе.

### Changed

- Телефон снова захардкожен константой `TEST_PHONE` в `config.js` — поле ввода
  на экране согласий убрано, номер вернётся из MAX вместе с мессенджером.
- Кеш справочников: вместо общего `lib/cache.js` по одной переменной на список
  в `api/branches.js` и `api/coworkers.js`.

### Removed

- `src/lib/` целиком: `storage.js` (девять ключей, половина не использовалась)
  и `cache.js` (обобщённый кеш ради двух справочников).
- Отладочный запрос `branch/index` из `App.vue` — он падал с необработанной
  ошибкой 401 в консоли.

## [0.1.9] - 2026-08-19

### Added

- Вход по номеру телефона: поле на экране согласий, нормализация ввода к виду
  `7XXXXXXXXXX`, сообщение «Клиент с таким номером не найден». Номер хранится в
  `localStorage`, поэтому сплэш пускает в профиль без повторного ввода.
- Подтверждение созданной записи: плашка «Ваша запись успешно оформлена!» поверх
  экрана с кнопкой «Перейти в профиль».

### Changed

- Сплэш вместо захардкоженного телефона вызывает `checkAuth()`: токен или
  сохранённый номер — в профиль, иначе на экран согласий.

### Removed

- Слой мессенджера MAX: `useMessenger`, SDK-скрипт в `index.html`,
  `initMessenger()` в `App.vue`. Приложение работает как обычное веб.
- Регистрация через мессенджер (`users/check-chat-id`, `users/register-telegram`)
  — она требовала `chat_id`. Пока доступен только вход по существующему номеру.

## [0.1.8] - 2026-08-18

### Added

- `src/components/ui/UiTabbar.vue` — нижняя плашка навигации (главная, запись,
  история) одним компонентом. Кнопка текущего экрана остаётся на месте, но
  ссылкой не становится (определяется по `route.path`).

### Changed

- Нижняя плашка липнет к низу экрана (`sticky bottom-2.5`) на `/profile` и
  `/active`: при прокрутке остаётся на виду, при коротком контенте прижимается
  к низу как раньше (`mt-auto`). Взяли `sticky`, а не `fixed`, — плашка
  остаётся в потоке, поэтому контент под ней не прячется.
- Разметка плашки больше не дублируется во вьюхах — обе используют `UiTabbar`.

## [0.1.7] - 2026-08-18

### Changed

- Слайдер записей на `/profile`: дата и время в одной строке по макету — дата
  занимает всю свободную ширину и не переносится. Подпись укоротили до
  «Чт, 1 сентября 2026» (без « г.», день недели с заглавной), шрифт строки —
  `text-13`, с 400px — `text-15`, стрелки слайдера стали тоньше. На совсем узких
  экранах дата обрезается многоточием, а не ломает плашку.
- Плашка врача в слайдере показывается всегда: без неё слайды прыгали по высоте,
  когда бэкенд не отдавал мастера. Если имени нет — «Врач не указан».
  Длинные названия услуг и имена врачей обрезаются многоточием.

## [0.1.5] - 2026-08-18

### Added

- `isCanceled()` в `src/api/appointments.js` — признак отменённой записи
  (статус `6`), строго по статусу и без оглядки на дату.

### Changed

- Экран `/active` стал историей записей: показываем весь список с сервера —
  актуальные, прошедшие и отменённые. Отменённые рисуются красным крестом
  (`HistoryCard` умел это с самого начала, но проп `canceled` никто не передавал).
  Заголовок — «История записей».

  `/profile` переведён на `current`, чтобы отменённые в него не попадали.

## [0.1.3] - 2026-08-16

### Added

- Создание записи: `POST /appointment/create` (`src/api/appointments.js`), тело
  собирает `useBooking.appointmentPayload()`. Кнопка «Записаться» отправляет
  запрос, показывает состояние отправки и текст ошибки от бэкенда; при успехе
  состояние флоу сбрасывается и происходит переход на главный экран `/profile`.
- Список всех текущих записей клиента на экране `/active`: `GET /appointment/index`
  (`filter[client_id]`, `sort=-date`), карточки `HistoryCard` — как на бывшем
  экране истории. Есть состояния загрузки, ошибки и «активных записей нет».
- Слайдер актуальных записей со стрелками на экране профиля — те же данные,
  что и на `/active`, но по одной записи на слайд. Без зацикливания: на краях
  соответствующая стрелка гаснет.
- `useAppointments` — загрузка текущих записей и форматирование полей
  (услуги, врач, дата, интервал времени) для обоих экранов.
- Кеш запросов на сессию (`src/lib/cache.js`): справочники запрашиваются один раз,
  результат отдаётся синхронно при повторном открытии экрана.
- Шторка «Правовая информация» на экране профиля (`LegalDialog.vue`) — модалка
  на весь экран с прокруткой; содержимое пока рыба (lorem ipsum), 14 разделов,
  перед релизом заменить на документы клиники.

### Changed

- Возврат назад по шагам записи больше не перезагружает данные: филиалы и врачи
  берутся из кеша, лоадер не показывается, ранее сделанный выбор (филиал, услуга,
  врач, дата) восстанавливается.
- Расписание по-прежнему запрашивается заново при каждом заходе на экран
  «Дата и время».
- Время на экране «Дата и время» — статичная сетка с шагом в час (11:00, 12:00,
  13:00 …). Из ответа `coworker/get-schedule` берутся только границы рабочего
  дня: первый и последний слот, неполный час на краях отбрасывается.
- Часы раньше «сейчас + 1 час» остаются видимыми, но недоступны для выбора
  (`disabled`); граница пересчитывается раз в минуту. Автовыбор и период
  (утро/день) открываются на первом доступном часе.
- В карточке записи строка с врачом скрывается, если врач в ответе не пришёл.

### Removed

- Отдельный экран истории записей (`/history`, `ViewHistory.vue`) — список
  переехал на `/active`.
- Карусель записей (embla) и кнопка «Отменить запись» на `/active` — вместо
  карусели список карточек.

## [0.1.1] - 2026-08-15

### Added

- Общий индикатор загрузки `UiLoader` на шагах записи: филиалы, услуги, врачи,
  свободное время.
- Слоты времени на экране «Дата и время» приходят из `coworker/get-schedule`:
  запрос по выбранным врачу, филиалу и дате, состояния загрузки, ошибки и
  «слотов нет».
- `payloadIds()` в `useBooking` — идентификаторы `client_id`, `master_id`,
  `branch_id` для тела запроса записи.

### Changed

- В календаре нельзя выбрать прошедшие даты (`min-value` — сегодня), начальная
  дата тоже сегодняшняя вместо зашитой.
- Периоды «9:00 - 13:00» и «13:00 - 18:00» стали фильтром по часу над слотами
  из API, а не отдельным списком времён.
- `doctorId` переименован в `masterId` — имена состояния записи совпадают с
  ключами API.
- Bearer-токен для запросов читается через `storage`, а не напрямую из
  `localStorage`.

## [0.1.0] - 2026-08-15

Первая собранная версия мини-аппы: вёрстка экранов и начало работы с API.
Ещё не подключено: создание записи (`appointments/create`), экраны активной
записи и истории (моки), должность и фото врача (заглушки), общий оверлей-лоадер.

### Added

- **Каркас приложения**: Vue 3 + Vite, vue-router с плоскими роутами и анимацией
  переходов, Tailwind v4 с токенами бренда в `src/style.css`.
- **Экраны**: сплэш, согласия, профиль, акции, услуги, категории, врачи, филиалы,
  выбор даты и времени, активная запись, история.
- **Связь с мессенджером MAX** — `useMessenger()`: данные пользователя из
  `window.WebApp`, `ready()`, запрос телефона; в DEV подставляется тестовый
  пользователь и номер.
- **Авторизация** — `useAuth()`: проверка клиента, регистрация через MAX,
  согласия. Токен и `user_id` хранятся в `localStorage` через `src/lib/storage.js`.
- **API-слой** на axios с Bearer-токеном: пользователи, акции (`promo/index`),
  филиалы (`branch/index`), сотрудники и их расписание (`coworker/index`,
  `coworker/view`, `coworker/get-schedule`).
- **Флоу записи** — `useBooking()`: филиал → услуга → врач → дата и время;
  услуги собираются из специалистов, врачи фильтруются по выбранной услуге.
- **Общие компоненты**: `UiBtn`, `UiPageTitle` (заголовок с кнопкой «назад»),
  `DoctorCard`, `HistoryCard`.
- **Конфигурация окружения**: `.env` / `.env.example` с `VITE_API_HOST` и
  `VITE_COMPANY_ID`, dev-прокси `/api` на хост бэкенда.
